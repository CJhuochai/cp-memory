# CP Memory 中文首发稿

## 标题

我给 AI 编码 Agent 做了一个本地记忆层：它不只会记住，还能解释和纠错

## 正文

每次新开 AI 编码会话，都重新解释一遍项目规则、个人偏好和历史决策，很快会变成一种重复劳动。

我做 CP Memory 的起点很简单：让重要上下文能在后续会话中按需恢复；但长期使用后，我发现更难的问题不是“AI 会不会忘”，而是“AI 记错了怎么办”。

所以 CP Memory 不追求把所有聊天都保存下来。它把规则、偏好、持续事项和决策保存在本地 SQLite 中，通过标准 stdio MCP server 恢复相关上下文；Codex 插件额外提供 Skills 和生命周期 Hooks 增强体验。记忆可以解释、纠正、过期和限定范围，而不是被静默覆盖。

一个最小例子：

```text
记住一下：这个项目发布前必须先开分支、跑测试、再通过 PR 合并。
```

之后在同一项目的新会话里，AI 编码 Agent 可以恢复这条规则，并按它继续工作。若规则不再成立，不是静默覆盖，而是可以标记为错误、过期或仅限某个项目。

我认为长期 AI 记忆应该满足四件事：

- 本地优先：默认不上传私人记忆；
- 按需恢复：不把无关项目的上下文混进来；
- 可解释：知道一条记忆来自什么；
- 可纠错：错误和过期不是简单删除，而是保留治理历史。

CP Memory 是一个开源 MCP 记忆服务，并提供增强版 Codex 插件。1.8.1 已发布到 [PyPI](https://pypi.org/project/cp-memory-mcp/1.8.1/)，并以 `io.github.CJhuochai/cp-memory` 注册到官方 MCP Registry。安装 Python 3.10+ 和 uv 后，可将 stdio MCP 客户端配置为运行 `uvx cp-memory-mcp`。公网干净缓存安装已通过 40 个工具握手及写入／查询／纠错冒烟。Windows 的 Codex Marketplace 和 macOS/Linux 的源码安装器仍受支持，并有三端 CI 覆盖；各客户端 UI 和审批流程尚未全部人工实测。它还没有图形化审阅界面；当前待审阅提醒注入给助手上下文，不是用户可见弹窗。

仓库、安装方式与脱敏演示脚本：

<https://github.com/CJhuochai/cp-memory>

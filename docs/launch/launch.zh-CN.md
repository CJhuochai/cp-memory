# CP Memory 中文首发稿

## 标题

我给 Codex 做了一个本地记忆插件：它不只会记住，还能解释和纠错

## 正文

每次新开 Codex 会话，都重新解释一遍项目规则、个人偏好和历史决策，很快会变成一种重复劳动。

我做 CP Memory 的起点很简单：让重要上下文能在后续会话中按需恢复；但长期使用后，我发现更难的问题不是“AI 会不会忘”，而是“AI 记错了怎么办”。

所以 CP Memory 不追求把所有聊天都保存下来。它把规则、偏好、持续事项和决策保存在本地 SQLite 中，通过 Codex 的 MCP 工具和生命周期 hooks 恢复相关上下文；同时保留解释、纠错、过期和范围限定能力。

一个最小例子：

```text
记住一下：这个项目发布前必须先开分支、跑测试、再通过 PR 合并。
```

之后在同一项目的新会话里，Codex 可以恢复这条规则，并按它继续工作。若规则不再成立，不是静默覆盖，而是可以标记为错误、过期或仅限某个项目。

我认为长期 AI 记忆应该满足四件事：

- 本地优先：默认不上传私人记忆；
- 按需恢复：不把无关项目的上下文混进来；
- 可解释：知道一条记忆来自什么；
- 可纠错：错误和过期不是简单删除，而是保留治理历史。

CP Memory 目前是一个面向 Codex 的开源插件，支持 Windows 的 GitHub Marketplace 安装；macOS/Linux 提供源码安装路径，并已有三端 CI 验证。它还没有图形化审阅界面；当前待审阅提醒注入给助手上下文，不是用户可见弹窗。

仓库、安装方式与脱敏演示脚本：

<https://github.com/CJhuochai/cp-memory>

欢迎反馈两个问题：你最希望 Codex 跨会话记住什么？以及，你如何判断一条 AI 记忆已经不该继续使用？

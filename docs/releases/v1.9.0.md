# CP Memory v1.9.0 — Recall quality / 召回质量

## 中文

- 恢复与召回共用有效性、范围和相关性筛选，减少无关最近记录和其他项目规则混入。
- 未确认自动候选带 `pending_review` 标记；保留泛问历史、偏好和只指定项目范围的查询。
- 修复 `allow_auxiliary=False` 未传入内层恢复的问题；保留实体名和正文证据检索。
- 增加可复现的 48 场景评估并接入跨平台 CI；固定回归集 144 项检查通过，禁止项出现次数从 111 降到 0。这不是实际用户准确率或 token 节约测量。

验证：61 项单元测试、20/20 个人记忆基准、144/144 召回检查、wheel/sdist 打包及 40 工具/5 次调用协议冒烟、Windows 隔离安装。合并以跨平台 CI 通过为前提。

兼容与升级：数据库格式及 40 个 MCP 工具参数保持不变，无需清理或迁移 `memory.db`。范围未知时不猜测当前项目，请在问题中明确项目、仓库或路径。词法检索和有限候选窗口仍有边界；macOS/Linux 真实桌面 Hook 手工验收不在本次自动化结论内。

通用 MCP：`uvx --from cp-memory-mcp==1.9.0 cp-memory-mcp`。Codex 插件更新后重启会话以加载新代码；旧运行进程不会自动热更新。

## English

- Share validity, scope and relevance selection across recall and restore, reducing unrelated recent records and other-project rules.
- Mark unconfirmed automatic candidates with `pending_review`; preserve broad history/preference and scope-only queries.
- Propagate `allow_auxiliary=False` into nested restore; retain entity-name and payload-evidence lookup.
- Add a reproducible 48-scenario suite to cross-platform CI. All 144 fixed regression checks pass; forbidden appearances decrease from 111 to 0. This does not measure population accuracy or model token savings.

Validation: 61 unit tests, 20/20 personal benchmark, 144/144 recall checks, wheel/sdist smoke with 40 tools and 5 protocol calls, and Windows isolated installation. Merge requires passing cross-platform CI.

Compatibility: unchanged database format and parameters for all 40 MCP tools; no `memory.db` cleanup or migration. Unknown project scope is not guessed: name the project, repository or path in the question. Lexical retrieval and a bounded candidate window remain limitations; real macOS/Linux desktop Hook manual acceptance is outside these automated claims.

Generic MCP: `uvx --from cp-memory-mcp==1.9.0 cp-memory-mcp`. Restart Codex sessions after updating the plugin; already running processes do not hot-reload the new code.
